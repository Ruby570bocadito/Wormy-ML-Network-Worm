## Detalle por cambio

### 1. `worm_core/report_cli.py` — revisión profunda del hub de reports

- **`_report_not_found(rid, reports_dir)` (nuevo)**: el bloque de error "Report not found … List available engagements with `report list`" estaba copiado ×4 (compare 1-id, compare 2-ids, show, html). Unificado en un helper junto a `load_report`. **Corrección de consistencia incluida**: en la rama de dos ids, `missing = id1 if a is None else id2` imprimía `'None'` literal cuando `id1` venía omitido (implícito `latest`); ahora aplica `id1 or LATEST` igual que la rama de un id — misma mejora de diagnóstico, mismo contrato de mensaje.
- **`_load_or_error(path, context)` (nuevo)**: el patrón `try: load_report … except (JSONDecodeError, OSError)` estaba ×3 (compare, show, html) con mensajes casi idénticos pero no iguales — la variante de compare **no incluía la ruta del archivo**. Devuelve `(data, EXIT_OK)` o `(None, EXIT_ERROR)`; el mensaje unificado siempre nombra la ruta (compare gana la ruta, show/html quedan byte-idénticos).
- **Pipeline de métricas table-driven**: `compare_metrics` definía un closure `fmt` distinto por `kind` dentro del bucle (con `# noqa: A001`) y encadenaba `if kind == "rate" / elif "dur" / else`. Ahora hay dos tablas de módulo — `_METRIC_PARSERS` (rate→`_parse_rate`, dur→`_parse_duration`, int→`_pass_through`) y `_METRIC_FORMATTERS` (rate→`_fmt_rate`, dur→`_fmt_dur`, int→`_pass_through`) — y el bucle se reduce a `parse, fmt = _METRIC_PARSERS[kind], _METRIC_FORMATTERS[kind]`. Añadir una métrica con kind nuevo revienta en un test de contrato (ver §4) en vez de en runtime. Semántica numérica preservada exactamente (el formatter de rate mantiene el passthrough de None; el de dur ya era None-safe).
- **`prune_flow`**: (a) `if as_json: pass` → `if not as_json:` (el `pass` con comentario colgando era el patrón más ruidoso del archivo); (b) `n_files = sum(...)` estaba computado dos veces (mensaje de dry-run y prompt de confirmación) — ahora una, antes de ambas; (c) el acumulador manual de tamaños del preview (`size = 0; for f: try: size += getsize …`) → `sum(_file_size(path) …)` con helper de 4 líneas.
- **`_resolve_ref`**: la variable local reasignada `rid = _report_id_from_path(path)` hacía shadowing del parámetro de entrada `rid`; renombrada a `derived_id`.

### 2. `worm_core/shell.py` — tokenizer REPL común

- **`_split_report_tokens(tokens, value_flags)` (nuevo, nivel de módulo)**: `_parse_report_html_args` y `_parse_report_compare_args` compartían el mismo esqueleto de bucle "consume `flag VALUE` o acumula como posicional" (~10 líneas ×2, mismas formas de error). El helper toma un spec `clave canónica → (aliases, mensaje de error)` y preserva la semántica exacta: posicionales en orden tipado, **último valor gana** si el flag se repite (incluso mezclando `-o`/`--output`), `ValueError` descriptivo cuando el flag queda de último token (lo renderiza `do_report` como error amable). Los dos parsers quedan en 5-7 líneas cada uno. `_parse_report_prune_args` **no se toca**: su forma (flags booleanos + enteros posicionales) es genuinamente distinta y forzarla al helper empeoraría el código.
- Constantes `_REPORT_OUTPUT_FLAG`/`_REPORT_METRICS_FLAG` documentan el spec — añadir un subcommand de report con flag de valor futuro es 3 líneas.
